## Section 1 — Login & chrome

**Routes:** `/login`

- Demo accounts listed; password hint `demo1234`.
- Bad password → clear error (not a silent hang).
- Good login → Dashboard (or intended home).
- Sidebar shows **role-appropriate** items (not necessarily all 11 for every role).
- User identity in sidebar (rank / name / callsign).
- Sign out → login; protected routes redirect when logged out.
- **My Jacket** works for the signed-in person.

**Multi-role spot check (required):**
1. Login as pilot → confirm Schedule/Ops/Admin not usable.
2. Logout → login as SDO → Schedule + Ops available.
3. Logout → login as maint → Maintenance workflows usable.

## Section 2 — Dashboard (`/`)

- Personnel metrics, aircraft readiness, currency warnings populate with data.
- **Stamped vs computed** status is understandable without tribal knowledge.
- WTM capability strip present and links to `/readiness`.
- Next 24 hours / scheduled sorties visible after fresh seed.
- Drift callouts if 614/615/617 scenarios exist.
- Cards/links navigate correctly; no empty error states without explanation.

---

## Section 3 — WTM Readiness (`/readiness`)

High bar for domain credibility.

- All 8 areas: MOB, FSO, ASU, SOF, PR, STW, LOG, MIW.
- Squadron overall T-rating and per-area T-1 / T-2 / T-3 counts.
- Drill-down: per-pilot contributing factors, anchor task current/stale/absent, windows shown.
- Aircrew rollup present.
- Export readiness brief PDF → download **or** explicit WeasyPrint/503 message (not silent fail).
- Copy does not confuse WTM T-ratings with Table B-2 personal currency.

Domain red flags: empty factors for degraded ratings, all-T-3 nonsense with full seed, missing areas.

---

## Section 4 — Maintenance (`/maintenance`, `/maintenance/{id}`)

**Rollup:**
- Computed FMC/PMC/NMC strip (not stamped-only).
- Phase / release forecast cards.
- Stamped vs computed drift visible when present.

**Aircraft by side number** (DB ids change each reseed — use side numbers):

| Side | Expected (fresh seed) |
|------|------------------------|
| 614 | Stamped FMC, computed PMC — QA release **allowed** |
| 615 | DOWNING / blocked QA release with reason |
| 617 | AWP / NMCS-style drift — QA release **blocked** |

**Detail page:**
- Inspections (overdue / downing flags).
- Discrepancies with MAF, JCN, work status, type WO.
- Work order chain; logbook entries; release forecast.
- New discrepancy / status updates work as maint role.
- QA Release: success path + blocked path both clear.
- Terminology: **QA release / safe for flight** — never **RTS**.

Use `morgan.david` for write actions if pilot is read-only on writes.

## Section 5 — Sortie cascade (product spine)

**Routes:** `/sorties`, `/sorties/{id}`, `/sorties/{id}/complete`, `/crew/{id}`

1. Find an **incomplete** live sortie (prefer NVG/night / ASU if present).
2. Open **Complete Sortie**.
3. Confirm validation for missing times / hours.
4. Fill takeoff/land, per-crew hours; try **per-crew landings** fields (Phase D).
5. Optionally add task credit / debrief notes.
6. Submit successfully.

Then on HAC crew jacket:
- Currency dates advanced when appropriate (e.g. night/NVG).
- Training jacket / readiness not obviously stale vs just-completed flight.

Optional: sim (TOFT) complete — non-sim-eligible currencies should not advance incorrectly.

## Known limitations (do NOT report as bugs)

- Unclassified synthetic demo — not a Navy enterprise system.
- WTM math is simplified Appendix D; CBR catalog is **Enclosure 2-shaped** (≈92 tasks), not a verbatim CHSCWPINST extract.
- Assisted scheduling is transparent heuristics, not optimization.
- PDFs need WeasyPrint on backend (503 with guidance is OK).
- Password reset is demo-only (admin resets to demo password).
- Multi-squadron and full 4790 configuration management are out of scope.
- Single-squadron portfolio demo; not production-hardened deployment.
